# Repository layout

The repository separates application source, example data, and generated output:

- **Source files** are the application and materials maintained in Git.
- **`dist/`** is generated by `pnpm build` and ignored by Git.
- **Imported trees and progress** are user data stored by the app in the browser.

## Folders

```text
loregrid/
├── src/                 TypeScript application, graph algorithms, renderer and worker
├── public/              Hosted assets and the explicitly curated public-tree catalog
├── data/
│   ├── examples/        Fictional example trees
│   ├── templates/       Starter templates to copy
│   └── compatibility/   V1 fixture used to test migration
├── docs/                User guides, format references, architecture and project notes
├── schema/              JSON schemas for tree and public-catalog formats
├── tests/               Unit tests, browser workflows and visual fixtures
├── scripts/             Validation, migration and benchmark commands
├── prompts/             Optional prompts for authoring tree JSON
├── README.md            Project overview and first-run instructions
├── index.html           Vite development entry
├── package.json         Commands and development dependencies
├── LICENSE              Loregrid and preserved upstream MIT terms
└── THIRD_PARTY_NOTICES.md
```

The `data/` folders contain examples, templates, and compatibility fixtures. They are
not the runtime tree library.

`public/trees/` is for JSON files intentionally included in the optional public catalog.
The current catalog is empty. `docs/assets/` contains documentation images only.

## Start and build

Run the app during development:

```powershell
pnpm install
pnpm dev
```

Build the standalone offline app:

```powershell
pnpm build
```

The generated entry point is `dist/index.html`. It contains the bundled application;
the TypeScript algorithms remain readable in `src/`.

## Tree and progress storage

Importing JSON copies its contents into the current browser's library. Loregrid does not
watch the source folder or edit the original file. Queues, completion, and notes are
stored separately in browser-local storage. Keep source files and export backups for
important data. See [privacy and storage](privacy.md).

For all guides, see the [documentation index](README.md).
