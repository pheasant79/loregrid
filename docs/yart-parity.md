# YART 行为对照

Loregrid 的工作基准是本项目记录的 YART 源码行为。下表区分已有实现、面向学习场景的适配和未完成部分；测试通过不代表已完整复刻 YART。

## 页面与使用

| 项目 | YART 源码位置 | Loregrid 当前行为 |
| --- | --- | --- |
| 顶部卡片 | `MainTabWindow_YART.QueueBar.cs` | 学习队列；点击定位，拖动排序，右上角 X 移出 |
| 分页与总览 | `MainTabWindow_YART.TopBar.cs` | 左上使用独立 All 与单一扁平分页下拉；私人组合分页保留。旧 V2 路径字段导入时忽略 |
| 选中节点 | `MainTabWindow_YART.Interaction.cs` | 普通点击打开左侧详情；代理跳转真实节点 |
| 快捷入队 | `MainTabWindow_YART.Interaction.cs` | Shift 点击追加前置链；Alt 点击优先；Ctrl 点击只保留该链 |
| 右键菜单 | `BuildNodeContextOptions` | 提供队列操作和详情／代理跳转；支持方向键和 Escape |
| 队列依赖顺序 | `ResearchQueueManager.EnsureTopologicalOrder` | 拖动、键盘排序和恢复进度后，前置项保持在后续项之前 |
| 移除排队项 | `ResearchQueueManager.DoRemove` | 移除未完成前置时，也移除依赖它的排队项；保留其他项和学习完成记录 |
| 清空队列 | `ResearchQueueManager` | 队列非空时显示“清空”；需确认，且不改完成记录和私人笔记 |
| 圆角框与曲线 | `Nodes.cs`、`Edges.cs` | 200 × 50 圆角卡片、曲线连接、长线虚拟节点路由；中间通道水平穿过列间，不穿过卡片 |
| 已完成状态 | `ResearchNode.cs`、`Nodes.cs`、`MainTabWindow_YART.Canvas.cs` | 节点完成使用统一绿色；全树阶段栏显示共享命名阶段、完成数和轻量阶段强调；不为主线／里程碑节点添加额外角标 |

此处队列表示学习安排。游戏自动科研、研究台频道、DLC、Harmony 和游戏存档不移入网页。学习完成状态、私人笔记和备份保持为独立数据。

## 视觉差异与近期修整

- 顶部采用“总览＋单一分页下拉”，旁边是学习队列；一棵树只有一个扁平分页集合，不再展示“路径／分页”双层关系。
- 阶段栏读取整棵树唯一的阶段名称和顺序；分页、组合页和 All 复用相同的阶段身份与完成统计。阶段不生成强制 rank；相邻阶段边界仅增加 50 世界像素的列间留白，以提供视觉呼吸感。没有真实阶段定义时不编造学科阶段，V1 阶段名称会随迁移保留；旧数据中同一序号出现冲突名称时合并为中性名称并给出警告。
- 示例节点较少是示例数据的选择，不是应用与 YART 的差异，本轮不通过塞入假节点来制造“密度”。
- 必需连线采用原生 Canvas 三次贝塞尔曲线，读取 YART 自有 `EdgeLine.png` 的透明度截面，并沿曲线按阶段边界局部过渡颜色；完成或未完成不会改变普通边的基础端口方向，Loregrid 不再给每条边画传统箭头。节点高扇入／扇出端口按稳定顺序分散，共享初始虚拟路由的长边共用起始端口。它仍不是 YART Unity/GL 渐变网格的逐像素复刻，沿活动路径的移动粒子也未实现。
- 节点在 110%–130% 缩放之间由 50 增至 66 个世界像素，并显示通用的节点类型、简介／成果和完成状态。YART 还显示研究花费、解锁图标、来源等游戏数据，Loregrid 不模拟这些不存在的学习字段。
- 悬停／选中会强调依赖邻域，但默认不把其他卡片压暗，这与 YART 默认关闭焦点压暗一致。焦点渐变动画和沿活动路径移动的脉冲仍未实现。
- 视觉曲线与端口此次按用户反馈做了专项修整；没有重写搜索或主布局排序算法。

## 布局内核

| 阶段 | 状态 | 说明 |
| --- | --- | --- |
| 必需前置的拓扑分层 | 已实现 | AND 依赖；推荐和相关关系不决定主层级 |
| `TightenRanks` | 已适配 | 在通用层级范围中收紧；不使用游戏时代 |
| `CompactRanks` | 已适配 | 压缩空列，坐标由布局计算 |
| 长边虚拟节点 | 已实现 | 渲染遵循虚拟节点路径 |
| 交叉优化 | 已适配 | Fenwick 树计数；多个确定性起始顺序、加权中位扫描、相邻交换、<=10节点精确子集 DP 和有限预算 sift；优化交叉数并纳入链条高度估计 |
| `SpringRelaxY` / `SpringPavProject` | 已适配 | 邻接弹簧松弛及非重叠投影；网页使用连续坐标 |
| `AlignTerminalLeavesToIncoming` | 已适配 | 末端节点向前置中心对齐，仅在不侵犯相邻间距时移动 |
| `BalanceRanks` / 列高预算 | 已适配 | 单一通用知识域使用软列高预算；按溢出、通道数、叶节点和稳定 ID 选择候选；局部目标函数作有限预算改进 |
| `ShapeChains` / `FitChain` | 已适配 | 以固定真实节点为端点，迭代拟合虚拟长边链；检测循环并恢复最少弯折的已见状态 |
| `UntangleChains` | 已适配 | 尝试相邻长边条带交换；仅接受不增加边界交叉且不使虚拟节点通道不可行的交换 |
| `ResolveDummyRuns` | 已适配 | 先用原间距、再用放宽的视觉间距解算连续纵坐标，并作最终分离保护 |
| 独立分页和 All 缓存 | 已实现 | Worker 内计算；可取消；离线单文件内嵌 Worker |

这不是逐行或逐像素复刻。网页保留树级学习阶段顺序作为通用概念，但不包含 RimWorld 的 `TechLevel` 枚举或专用规则；使用连续坐标而不做 YART 网格吸附；后代排序使用封顶的路径权重近似，避免显式存储可能呈平方增长的后代集合；列平衡、局部排序和条带尝试均有确定性工作预算。预算只缩减可选优化，不限制输入节点数量。不能保证和 YART 对同一张图产生完全相同的节点顺序或坐标。

## 已有验证与边界

2026-11-18 RC5：36 项单元测试、Chromium 26/26、Firefox 26/26、类型检查、演示树验证、单文件构建和离线 `file:` 打开通过。10,000 节点页面交互样本：Chromium 中位 6.7ms／P95 9.0ms；Firefox 中位 9.0ms／P95 13.0ms。截图分别保存在两个浏览器的视觉基线目录。Firefox 专用 Playwright 浏览器已安装并实际运行。

2026-11-18 RC3：36 项单元测试、24 项 Chromium 浏览器测试、类型检查、演示树验证和离线单文件构建通过。新增浏览器验收覆盖高缩放卡片信息、焦点时无关卡片仍可见、扩高后无节点相交；10,000 节点用例中的 1,000 节点分页缩放样本为中位 19.6ms / p95 24.1ms（仅本机一次运行）。Firefox 当时尚未通过页面行为验证。

2026-11-14：高级布局更新后，32 项单元测试和 19 项 Chromium 浏览器测试通过。浏览器测试覆盖队列快捷键与依赖删除、右键菜单、分页、搜索、备份恢复、旧版数据、离线打开和一万节点压力用例。性能数据和具体适配边界见 `docs/performance.md`。

没有实际客户数据的验收结果；本文件不是客户签收，也不表示布局内核逐行或输出坐标完全等价。

## RC4 — 当日反馈修整（2026-11-18）

客户拒绝了 RC3。结合本轮截图，RC4 优先处理一眼可见的工作台差异：移除独立品牌横幅，将品牌、树名称和打开／菜单／语言操作并入左上控制区；分页、搜索与学习队列共用顶部区域；分页色不再整块填充节点卡片，改为统一深色底和细边框，标题靠左、状态符号靠右；普通连线改为统一灰蓝色，完成／焦点路径继续突出；初始“适配视图”不再把小树放大到 100% 以上。

验证：`pnpm check`；`pnpm test` 36/36；演示树校验 20 节点／4 分页；Chromium 25/25（单 worker，包含 10,000 节点用例和 `file:` 离线打开）；生产构建成功；`git diff --check` 通过。压力用例的 1,000 节点分页帧样本为中位 10ms／p95 12.1ms，仅代表本机该次运行。更新了 compact-workbench、fieldwork、queue/details、rich-cards 与 narrow-board 截图基线。

RC4 当时未验证：Firefox、完整无障碍审计、真实客户树／流程验收。RC4 不代表客户已接受或已实现完整 YET 等价；Firefox 已在后续 RC5 中通过自动化回归。

## RC5 — 跨浏览器交付候选（2026-11-18）

在 RC4 的基础上，分页下拉现在会在多路径树里明确显示“路径／分页”，避免分页标题唯一时仍不知道所属路径；适配视图图标改为内嵌 SVG，避免浏览器字体映射不一致。详情操作和前置条件说明、清空队列固定位置、统一节点底色和连线色均已通过两种浏览器回归。阶段栏现在只接受树级阶段表：所有分页和 All 使用同一套阶段标题，画布绘制淡色纵向区域、顶部标题和细竖向边界；V1 阶段名称会保留，冲突的旧分页阶段会在迁移时合并并警告。没有真实阶段数据时不编造名称。

RC5 不是严格 YART 等价或客户验收结论。真实客户树和操作流程、完整无障碍审查仍待确认。

## RC8 — 布局与分页收敛（2026-11-19）

- 页面选择器统一为“总览＋扁平分页”；旧 V2 `paths` 和 `pathId` 只为导入兼容保留，运行时不参与视图筛选。
- 移除阶段提示导致的额外布局列和人为间距；阶段仍用于标注、颜色及完成状态，节点主层级由必需依赖布局计算。
- 连线依沿线贝塞尔采样，在阶段边界附近进行局部颜色过渡，并沿用 YART 自有 `EdgeLine.png` 的透明轮廓。该 Canvas 实现与 YART Unity/GL 的渐变带不是逐像素等价移植。
- 这些收敛不代表布局输出与 YART 完全一致；排序、坐标和绘制仍有适配差异。

## RC8 — 阶段间距、曲线和汇聚连线修整（2026-11-19）

- 阶段边界在相邻布局列之间添加 50 世界像素的视觉留白，不改变由 required 依赖决定的 rank。
- 必需边改为 Canvas 原生三次贝塞尔曲线，沿曲线的阶段色只在阶段边界附近过渡；保留 YART 纹理轮廓。具体 Unity/GL 渐变带和粒子动画未移植。
- 去掉传统逐边箭头；高扇入与高扇出节点采用稳定的分散入口/出口端口；同一共享长边起始走廊共用首个端口/曲线段。
- 2026-11-19 单 worker Chromium/Firefox 10k 节点交互样本的 pan/zoom P95 为 13.6/13.9 ms 与 11/12 ms；数据只代表本机本次 fixture。一次性 All 布局在独立 benchmark 中报告，不与交互帧耗时混合，见 `docs/performance.md`。
- 单测和全量 Playwright 均通过；截图更新基线已分别覆盖 Chromium 与 Firefox。此结果不代表客户验收或逐像素 YART 等价。
